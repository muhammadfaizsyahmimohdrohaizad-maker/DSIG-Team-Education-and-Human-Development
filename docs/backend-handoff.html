What changed on the front end

  • Removed

    Review, learning, lessons and mastery checks

    features/review, features/learning, the routes /plan/review, /plan/learn, /plan/check, /plan/lessons, server/data/review.ts and two unit tests that covered the review code.

  • Removed

    Hard-coded sample data

    The four sample files behind the student and adviser headers, the dashboard and parent consent are deleted, along with the homepage sample. Those screens now read real rows through server/data. supabase/seed.sql is untouched.

  • Built

    Screens that were placeholders

    Map, Skill gap, Plan, Progress, Résumé, Book, My appointments (new route /book/appointments), Appointment detail, Settings, Staff undertaking, and the adviser pages for Requests, Students, Cohort and Availability. They use the existing server actions.

  • Changed

    Adviser gate

    app/adviser/layout.tsx now redirects to /staff/undertaking when has_current_undertaking is false. Before, an adviser could open adviser pages without accepting the undertaking.

New or changed code in your area

All of these follow the existing patterns. Please check the query shapes against the real database: I could not run them, because local keys weren't available.

  • Review

    recentAnswers(userId, limit) in server/data/interview.ts

    Read-only, user client, own rows only. Reads interview_answers, then ref.interview_questions by id for the round and prompt. Used by the Progress page.

  • Review

    adviserStudents() in server/data/adviser.ts, and listStudents in features/adviser/actions.ts

    Calls the existing adviser_students RPC, which no code called before. I assumed each item in upcoming (Json) has slot_start or start, plus status. Please confirm the shape.

  • Review

    loadCv in features/cv/build.ts, and CvView.skills in lib/types.ts

    The CV listed only skills with a passed mastery check, so it would always be empty now. It now lists skills with evidence: skills the student added, or skills covered by a passed module or SPM result (shownSkills), plus any earlier passed check. Target-job skills come first. The type changes from masteredOn to evidence and forTarget.

  • Review

    Skill-gap wording in features/plan/gap.ts

    The evidence text no longer mentions lessons or the 5-question check. The logic is unchanged.

  • Review

    Development-only CSP in next.config.ts

    Next's development runtime needs 'unsafe-eval'. Without it, React never started on localhost, so no button or form worked. It's added only when NODE_ENV === "development", so production headers are unchanged.

Bugs that need a backend change

  • Blocker

    "I already know this" leaves a skill stuck

    claimSkill sets check_needed, and only a passing mastery_checks row moved it on (guard_mastered). The check screens are gone, so a claimed skill can never become "have". The new design says "Needs evidence: add a project, certificate or document that shows it". It needs an evidence store (link or file, kind, review status) and a rule that moves the skill to have. Until then, the front end shows "Needs evidence" with no way to finish.

  • Blocker

    "How recommendations work" page vs the matching engine

    The design states score = 70% essential skills + 20% optional skills + 10% interest fit. server/engines/matches.ts uses WEIGHTS = { skill: 2, interest: 3, project: 1, jobInMind: 2 }. The page isn't built so we don't publish a false claim. Either the engine or the copy has to change first.

  • Design

    Sharing can't be changed after booking

    The design lets a student change what an adviser sees from the appointment page. There is no action to update bookings.shared_items, so the list is read-only for now.

  • Design

    No action for booking emails

    profiles.reminder_emails exists, but nothing updates it. The Settings switch is hidden until there is one.

Leftovers from the removed features

The front end no longer reads or writes any of these. Decide whether each one is dropped or kept for later. AGENTS.md says to remove code when a feature is replaced.

  • Clean-up

    Tables

    review_cards, lesson_progress and mastery_checks, with their RLS policies, and the ref lessons and check questions loaded by scripts/import-reference.ts from content/lessons.

  • Clean-up

    Functions in server/data/learning.ts

    addReviewCards, markLessonDone, getNotes, recordCheck and setLearningState are now unused. getProgress, claimSkill and the saved-option functions are still used by Plan, Skill gap and CV.

  • Clean-up

    Engines and dependencies

    server/engines/lesson.ts (only PASS_MARK is still used, by claimSkill) and the lessonsLeft engine in features/plan/gap.ts. The ts-fsrs dependency was only for review cards.

  • Clean-up

    Database logic that still assumes lessons

    student_skill_states, behind open_request and adviser_students, derives states from checks and lessons. The ai_calls.kind value notes_cards and the AI budget belonged to the notes-to-cards feature. Data export and deletion still walk these tables.

  • Review

    Privacy Notice and parent-consent wording

    The front end changed both to stop mentioning mastery checks and lesson notes. The Privacy Notice now says "To track your practice: your skill progress, your résumé and the marks on your mock interview answers." Whoever owns the notice should sign this off, and update the data inventory if the lesson tables are dropped.

  • Blocker

    Sign-up asks students to agree to Terms that aren't written

    The sign-up form requires "I agree to the Terms & Conditions" and records a terms_privacy consent, but there is no Terms text. /terms now says the terms aren't published yet, and the footer link is hidden. The team needs to publish the terms, or decide what the required consent covers until then.

Local setup notes

  • Blocker

    Keys for local testing

    The front end needs a dev or staging project: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY and CRON_SECRET in .env.local, plus one test student and one test adviser. To create an adviser through sign-up, it also needs STAFF_CODE_HASHES.

  • Note

    Node and pnpm

    package.json asks for Node 22. The machine used here has Node 24 and worked. corepack enable needs admin rights on Windows, so run corepack pnpm … instead.
